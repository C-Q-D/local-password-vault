## 总体方案

- 目标：按照用户可以在前端直接验证的顺序，逐步完成本地密码库 MVP。
- 范围：Windows 第一版的启动、分类、账号、搜索、密码查看与复制、加密持久化、保存失败和备份恢复。
- 开发方式：每个交付单元同时包含一个后端行为和对应前端入口；后端完成但前端无法操作或观察时，该单元不算完成。
- 验证方式：每个单元先通过聚焦自动测试，再启动 Tauri Debug 程序，由用户按单元验收场景直接验证。
- 明确不包含：云同步、在线账号、浏览器插件、自动填充、手机端、多人共享、导入导出、独立设置页，以及开发期间的 Release 构建和性能优化。

### 能力推进顺序

1. 建立真实加密空库和可直接使用的主界面。
2. 逐项完成分类管理，每一步都能从侧边栏验证。
3. 逐项完成账号新增、编辑、移动和删除，每一步都能从表单、列表和详情验证。
4. 增加搜索、密码显示与剪贴板操作。
5. 增加保存失败和备份恢复的用户可见处理。
6. 全部功能完成后再进入整体验收；Release 和性能验证继续推迟到发布候选阶段。

## 全局业务不变量

- 磁盘不得保存账号字段明文，普通日志不得输出账号名、密码、地址、邮箱或备注。
- 账号和分类使用稳定 ID；编辑、移动和删除一条记录不得改变其他记录。
- “全部”和“未分类”是计算视图，不写入用户分类，也不能重命名或删除。
- 账号名和密码必填；地址、邮箱和备注可空；账号名、地址和邮箱均不设置唯一约束。
- 非空分类不能删除。
- 搜索只匹配账号名、地址、邮箱和备注，不匹配密码。
- 每次成功修改自动保存；保存失败时，前端和内存继续显示上一次成功提交的数据。
- 所有前端写操作通过 Tauri command 进入同一个 Rust 写入所有者；前端不直接读写密码库文件。
- 每完成一个交付单元，必须报告验证结果和剩余交付单元。

## 跨单元约束

- 每个单元都必须形成“前端触发 → Rust 处理 → 持久化或读取结果 → 前端展示”的真实闭环。
- 只修改前端时使用类型检查和 Vite HMR；Rust 改动优先目标 crate 检查与相关测试；完成单元后再做必要的 Tauri Debug 冒烟。
- 自动测试使用隔离临时目录和合成账号，不访问用户正式密码库或真实剪贴板。
- Release 构建、安装包、包体积和最终性能测量不在开发单元中执行。

## 交付单元卡

### LPV-01 首次启动并进入加密空库

- 状态：done
- 用户价值：第一次打开 App 就能直接进入可用主界面，不需要配置服务器或主密码。
- 后端结果：取得单实例锁，在本机数据目录创建或加载 AES-GCM 加密空库，数据密钥由 DPAPI CurrentUser 保护；关闭并重新打开后仍能加载同一空库。
- 前端验证入口：启动 App 后看到分类区、账号区、搜索入口和“暂无账号”空状态。
- 触发与前置条件：隔离测试数据目录中不存在任何密码库痕迹。
- 验收场景：启动 App，确认直接进入空状态；关闭并重开，仍正常进入同一空状态；磁盘文件中不存在可读账号 JSON。
- 来源：FR-01、FR-08、AC-01、AC-09。
- 明确不包含：分类和账号的增删改查、备份恢复界面、Release 构建。
- 依赖：无。
- 风险：这是第一条真实持久化切片，必须同时证明 DPAPI、AES-GCM、原子首次发布和 Tauri 前端载入，不能用内存 Mock 代替。

### LPV-02 创建分类

- 状态：done
- 用户价值：用户可以创建自己的账号分类。
- 后端结果：校验分类名非空且不与现有分类重复，生成稳定 ID，保存并返回最新分类快照。
- 前端验证入口：侧边栏“新建分类”入口和名称输入框。
- 触发与前置条件：App 已正常载入；输入非空分类名。
- 验收场景：创建“工作”分类后，它立即出现在侧边栏；关闭重开后仍存在；空白或重复名称显示校验提示且不保存。
- 来源：FR-02、AC-02。
- 明确不包含：重命名、删除分类、创建账号。
- 依赖：LPV-01。
- 风险：写入失败时不能把临时分类留在前端列表。

### LPV-03 重命名分类

- 状态：done
- 用户价值：用户可以修正已有分类名称。
- 后端结果：按稳定 ID 更新指定分类名称并保存，不改变分类内账号归属。
- 前端验证入口：用户分类的重命名入口和名称编辑框。
- 触发与前置条件：至少存在一个用户分类。
- 验收场景：把“工作”改为“开发”后，侧边栏立即更新；空白或与其他分类重复的名称被拒绝；系统视图没有重命名入口。
- 来源：FR-02、AC-02。
- 明确不包含：删除分类、移动账号。
- 依赖：LPV-02。
- 风险：必须按 ID 更新，不能按名称误改其他分类。

### LPV-04 删除空分类

- 状态：done
- 用户价值：用户可以移除不再需要的空分类。
- 后端结果：确认分类存在且账号数量为零后，按稳定 ID 删除并保存。
- 前端验证入口：空分类的删除入口和确认提示。
- 触发与前置条件：存在一个空用户分类。
- 验收场景：确认删除后分类从侧边栏消失，重开后不再出现；取消确认时不发生变化；系统视图没有删除入口。
- 来源：FR-02、AC-02。
- 明确不包含：非空分类阻止逻辑，该行为由 LPV-06 验收。
- 依赖：LPV-02。
- 风险：前端确认只表达用户意图，Rust 仍必须重新检查分类是否为空。

### LPV-05 新增账号

- 状态：done
- 用户价值：用户可以保存第一条以及同一网站的多条独立账号。
- 后端结果：校验账号名和密码必填，生成稳定 ID，允许地址、邮箱和备注为空，也允许地址重复，保存后返回最新列表与详情。
- 前端验证入口：新增账号表单、账号列表和账号详情。
- 触发与前置条件：App 已载入；可以选择用户分类或“未分类”。
- 验收场景：保存完整账号后列表立即出现并可查看详情；空账号名或密码时字段附近提示且不保存；连续创建两个相同地址的账号，两条记录都存在且 ID 不同；关闭重开后记录仍存在。
- 来源：FR-03、FR-04、FR-05、AC-04、AC-05、AC-06、AC-09。
- 明确不包含：编辑、移动、删除、搜索和复制。
- 依赖：LPV-01；建议先完成 LPV-02，以便同时验证分类归属。
- 风险：列表结果不得包含明文密码，详情只返回当前显示所需数据。

### LPV-06 阻止删除非空分类

- 状态：done
- 用户价值：用户不会因删除分类而误丢失或无意改变分类内账号。
- 后端结果：删除前在当前已确认快照中重新计算账号数量；非零时返回稳定错误且不保存。
- 前端验证入口：包含账号的分类删除入口和明确错误提示。
- 触发与前置条件：某个用户分类下至少存在一个账号。
- 验收场景：尝试删除该分类时操作被阻止，分类和账号保持原样，并提示先处理分类内账号。
- 来源：FR-02、AC-03。
- 明确不包含：自动移动账号、级联删除或回收站。
- 依赖：LPV-02、LPV-05。
- 风险：不能只依赖前端显示的账号数量。

### LPV-07 编辑账号字段

- 状态：done
- 用户价值：用户可以修正指定账号的账号名、密码、地址、邮箱和备注。
- 后端结果：按稳定 ID 更新指定账号并重新执行必填校验，其他账号保持不变。
- 前端验证入口：账号详情中的编辑表单。
- 触发与前置条件：至少存在一条账号记录。
- 验收场景：修改字段并保存后，列表和详情立即显示新值；把账号名或密码清空时保存被阻止；相同地址的另一条账号不受影响；重开后修改仍存在。
- 来源：FR-03、FR-04、FR-05、AC-04、AC-05、AC-06、AC-09。
- 明确不包含：移动分类和删除账号。
- 依赖：LPV-05。
- 风险：前端 Draft 未保存前不得改变已确认列表快照。

### LPV-08 移动账号分类

- 状态：done
- 用户价值：用户可以把账号移动到其他分类或“未分类”。
- 后端结果：确认目标分类存在后，按账号稳定 ID 更新分类归属并保存。
- 前端验证入口：账号编辑表单中的分类选择器。
- 触发与前置条件：至少存在一条账号；移动到用户分类时目标分类必须存在。
- 验收场景：保存后账号从原分类列表消失并出现在目标分类；移动到“未分类”后可在该系统视图看到；其他字段保持不变。
- 来源：FR-05、AC-06。
- 明确不包含：创建分类、批量移动和拖拽排序。
- 依赖：LPV-02、LPV-05。
- 风险：目标分类在保存前已不存在时必须拒绝，不能形成悬空引用。

### LPV-09 删除账号

- 状态：in_progress
- 用户价值：用户可以明确确认后删除一条指定账号。
- 后端结果：按稳定 ID 删除指定账号并保存，其他记录不变。
- 前端验证入口：账号详情中的删除按钮和确认框。
- 触发与前置条件：至少存在一条账号记录。
- 验收场景：取消确认时记录不变；确认后该账号从列表和详情消失；同地址账号仍存在；关闭重开后被删除账号不会恢复。
- 来源：FR-04、FR-05、AC-05、AC-06、AC-09。
- 明确不包含：回收站、批量删除和撤销。
- 依赖：LPV-05。
- 风险：确认后仍按稳定 ID 删除，不能使用当前列表位置。

### LPV-10 搜索和分类筛选

- 状态：pending
- 用户价值：用户可以在全部账号或当前分类中快速定位账号。
- 后端结果：在已确认内存快照中按账号名、地址、邮箱和备注进行不区分大小写的包含搜索，明确排除密码字段，并返回不含密码的列表结果。
- 前端验证入口：搜索框、全部/未分类/用户分类侧边栏和无结果空状态。
- 触发与前置条件：存在多条具有不同字段和分类的账号。
- 验收场景：分别输入账号名、地址、邮箱和备注片段都能命中；只输入密码内容不能命中；选择分类后只返回该范围记录；无匹配时显示明确空状态。
- 来源：FR-06、AC-07。
- 明确不包含：模糊评分、搜索历史、高亮和高级过滤器。
- 依赖：LPV-05；分类范围验证依赖 LPV-02、LPV-08。
- 风险：搜索结果和日志都不能泄露密码。

### LPV-11 查看和复制账号凭据

- 状态：pending
- 用户价值：用户可以临时查看密码，并安全复制账号名或密码。
- 后端结果：按稳定 ID 获取当前字段；Windows 复制密码时写入 token、sequence 和历史/云同步排除格式，30 秒后仅在剪贴板仍属于本次写入时清除。
- 前端验证入口：密码显示/隐藏按钮、复制账号按钮和复制密码按钮。
- 触发与前置条件：至少存在一条账号记录。
- 验收场景：密码默认隐藏，点击后临时显示并可再次隐藏；复制账号后可粘贴正确账号名；复制密码后可粘贴正确密码；30 秒内复制其他内容不会被 App 清除；没有把密码写入日志。
- 来源：FR-07、AC-08。
- 明确不包含：自动填充、剪贴板历史管理和崩溃后的绝对清除保证。
- 依赖：LPV-05。
- 风险：必须在同一次剪贴板锁内完成比较和条件清除，不能先读后无条件清空。

### LPV-12 保存失败保持旧数据

- 状态：pending
- 用户价值：保存失败时用户能看到明确错误，上一份成功数据不会被破坏或伪装成新数据。
- 后端结果：写 temp、替换、重验任一步失败时返回稳定错误；普通提交前失败继续保留旧 main 和旧内存快照；Windows 替换错误 1177 进入专用恢复分支。
- 前端验证入口：新增、编辑或删除操作后的保存失败提示，以及仍显示旧数据的列表和详情。
- 触发与前置条件：隔离测试环境注入可控保存失败，且已有一份成功保存的账号数据。
- 验收场景：编辑账号时触发保存失败，界面提示失败并恢复到旧值；重新打开 App 仍是旧值；失败期间不产生假成功提示。
- 来源：FR-08、AC-10。
- 明确不包含：自动无限重试、后台同步和通用故障诊断页。
- 依赖：LPV-07；删除失败场景依赖 LPV-09。
- 风险：这是数据安全检查点，测试必须使用工具创建的隔离临时目录，不操作用户正式密码库。

### LPV-13 从有效备份恢复

- 状态：pending
- 用户价值：主库损坏但上一版备份有效时，用户可以确认恢复并继续使用上一份数据。
- 后端结果：启动时分别认证 main 和 backup；只有 backup 有效时进入待恢复状态；用户确认后从 backup 复制到唯一 temp、重验并发布为 main；恢复失败则保持不可编辑并保留现场。
- 前端验证入口：专用恢复提示、确认按钮、恢复中状态、成功后的主界面以及失败时的不可编辑状态。
- 触发与前置条件：隔离测试目录中 main 损坏或缺失，backup 有效。
- 验收场景：启动后不创建空库覆盖现场；确认恢复后看到上一版账号；取消时不写文件；main 和 backup 都无效时只显示不可编辑错误状态。
- 来源：技术设计中的恢复要求，保护 FR-08、AC-09、AC-10。
- 明确不包含：跨电脑、系统重装、其他密码管理器导入和自动静默恢复。
- 依赖：LPV-05、LPV-12。
- 风险：恢复过程中 backup 必须保持只读，不能把未认证内容发布为 main。
