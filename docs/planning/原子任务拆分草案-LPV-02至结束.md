# LPV-02 至 LPV-13 原子任务拆分草案

> 本文件是并行规划草案，只拆分父计划中尚未开始的 LPV-02 至 LPV-13，不替代当前正在执行的 LPV-01 原子计划，也不改变父计划状态。

## 草案元数据

- 来源计划：`SCOPE-LPV-MVP-001`
- 覆盖范围：LPV-02 至 LPV-13
- 规划基线：`87a37a9176ad4f81f4a150bb5cb46a2384c7d25c`
- 原子总数：45
- 推荐模式：每次只激活一个交付单元；单元内按依赖连续逐原子开发、验证和提交。
- 前后端节奏：每个交付单元的领域/存储原子完成后，立即完成对应 command、TypeScript 调用和前端入口，不跨单元积压界面。
- Git 策略：执行时每个原子独立提交；提交标题必须包含原子 ID；远端同步按执行时有效授权和仓库规则处理。

## 已确认现状与接缝

- `vault-core` 承担 `VaultDocument`、分类、账号、搜索和校验，不依赖 Tauri 或平台 API。
- `vault-storage` 承担认证加密信封、保存、备份与恢复；平台文件原语从外部注入。
- `vault-app` 是已确认快照和单写者边界；候选保存失败时不得替换内存快照。
- `src-tauri/src/commands/` 是薄 command 层；`frontend/src/lib/tauri/commands.ts` 是前端唯一 IPC 边界。
- 前端整体布局由 LPV-01 的参考图原子确定；本草案只在其实际组件结构上增加当前功能，不自行重做整体视觉。
- 当前前端没有自动测试框架，前端原子默认用 `npm run check` 和 Tauri Debug 人工冒烟验证，不为单个功能引入新测试框架。

## 跨原子不变量

- 新增说明性注释使用中文；公共契约、安全边界、状态提交、回退与非直观平台代码必须说明原因，直观代码不写复述式注释。
- 每次成功业务提交只增加一次 `revision`；失败候选不得污染已确认快照。
- 列表与搜索 DTO 不含明文密码；普通错误和日志不含账号字段、密钥、密文内容或用户数据路径。
- “全部”和“未分类”始终是计算视图，不创建持久化 ID，不可重命名或删除。
- 所有写操作按稳定 UUID 定位；账号名、地址、邮箱不唯一；账号名和密码拒绝空白字符串。
- 前端只通过 Tauri command 访问数据；表单使用 Draft，Rust 成功返回新快照后才替换界面已确认状态。
- 自动测试只使用合成账号和工具创建的临时目录，不读写用户正式密码库，不使用真实剪贴板内容。
- 遵守 `docs/development/编译策略.md`：先窄检查，功能单元末尾才做工作区回归；全程不执行 Release、`cargo clean` 或删除 `target`。

- 当前行为与目标行为：LPV-01 只支持首次不覆盖发布；完成后可从同目录 temp 替换 main 并生成 `backup-next`。
- 前置条件与依赖：LPV-01 的首次文件接口和路径所有权；`Windows平台能力方案.md`。
- 代码定位依据：`crates/vault-platform-windows/src/atomic_file.rs` 与 `vault-storage` 已定义的文件接口。
- 允许修改：Windows 文件原语、精确 Win32 feature（只有确实缺失时）、临时目录集成测试；状态记录。

- 实现步骤：同目录唯一 temp 已写完并同步后调用 `ReplaceFileW`；成功后以 `MoveFileExW(REPLACE_EXISTING|WRITE_THROUGH)` 晋升 backup；明确返回“main 已提交但备份晋升失败”结果。
- 接口、数据与错误契约：区分提交前失败、main 已提交和 backup 晋升失败；错误不包含文件内容。
- 边界与异常：本原子不吞掉 1177，但先以独立错误类别交给 LPV-12；只删除本次确定拥有的 temp。
- 测试要求：替换后 main 为新字节、backup 为旧字节；普通替换失败保持旧 main；备份晋升结果可区分。
- 验证命令：`cargo test -p vault-platform-windows atomic_file`；`cargo check -p vault-platform-windows`；格式检查。
- 预期结果：隔离目录中正常替换路径成立，不触碰用户文件。
- 完成判定：文件原语能准确报告磁盘提交点，测试覆盖旧 main/backup 内容。
- 交付给下一原子的输出：存储层可调用的“已有 main 原子替换”接口。
- 停止或重新规划条件：当前接口无法表达 main 已提交但备份失败，或 temp 与 main 不能保证同目录。
- 风险等级：L3
- DDD 门禁：实现前只质疑“成功返回时 main 是新候选且 backup 是紧前旧 main”；执行时按 DDD 规则隔离审查。

## 每个交付单元的回归边界

- 领域原子：目标 `vault-core` 测试、`cargo check -p vault-core`、格式检查。
