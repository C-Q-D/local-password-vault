## 总体计划

- 产品结果：用户能在正式侧边栏创建、重命名和删除分类，所有操作真实保存到加密密码库，重启后保持一致。
- 验收场景：分类名称非空且不重复；创建和重命名成功后立即显示；空分类删除前确认；非空分类删除被 Rust 拒绝并提示；取消操作不写入；重开后结果保持。
- 明确排除：账号新增和编辑、分类筛选账号列表、搜索、密码操作、备份恢复、Release 构建和整体界面重做。
- 现状证据：`VaultDocument` 已有分类和账号结构但无分类行为；`VaultFiles` 只有首次发布；`VaultApplication` 只持有不可变启动摘要；Tauri 只有 `load_vault`；正式 Svelte 已预留分类区。
- 核心规则：名称保存前 `trim`；唯一性比较使用 Unicode 小写结果；系统视图不持久化；所有写入先克隆候选，磁盘提交并重验成功后才替换应用快照；分类账号数量由 Rust 当前账号引用计算。
- 安全边界：前端永远不接收密码；测试只使用内存 Fake 或 `tempfile`；不操作用户真实密码内容；错误响应只使用稳定代码和固定中文信息。
- 执行模式：连续执行，每个原子独立验证、提交并推送 `origin/master`。
- 整体回归：受影响 crate 测试、`npm run check`、`cargo test --workspace`、真实 Tauri Debug 创建/重命名/删除/重开冒烟；不执行 Release。
