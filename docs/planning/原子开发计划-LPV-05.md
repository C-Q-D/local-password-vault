# LPV-05 新增账号原子开发计划

## 计划元数据

- 计划 ID：ATOMIC-LPV-05-001
- 类型：atomic-development
- 修订版本：1
- 状态：active
- 父级 ID：LPV-05
- 创建基线：`e79880e`

## 总体计划

- 产品结果：用户能从正式界面保存第一条账号，保存后立即看到真实列表，重启后记录仍存在。
- 验收场景：账号名和密码必填；地址、邮箱、备注可空；分类可选择用户分类或未分类；相同地址可保存多条独立记录。
- 明确排除：账号编辑、移动、删除、搜索、密码显示、密码复制和整体视觉重做。
- 已确认架构：`vault-core` 维护领域文档；`vault-app` 串行提交确认快照；Tauri command 只做 DTO 转换；Svelte 只消费 Rust 返回的确认结果。
- 全局不变量：列表 DTO 不含密码；普通错误和日志不含账号字段；失败提交不替换前端或应用层已确认状态；每次成功只增加一次 revision。
- 执行模式：连续执行，四个原子各自验证、提交并同步后进入下一原子。
- 整体回归：`cargo test --workspace`、`cargo check -p local-password-vault`、`npm run check`、Tauri Debug 冒烟；不执行 Release。

## LPV-05-01 创建账号候选并校验字段

- 状态：in_progress
- 支持的验收场景：必填正确创建；可选字段可空；相同地址账号互不覆盖。
- 唯一目标：`vault-core` 能创建一条字段有效、分类引用有效且 ID 独立的账号候选。
- 当前行为与目标行为：当前只有账号数据结构；完成后可通过领域方法追加账号。
- 前置条件与依赖：LPV-01、LPV-02 已完成。
- 代码定位依据：`crates/vault-core/src/vault.rs` 的 `VaultDocument`、`Account` 和统一校验；`crates/vault-core/src/error.rs` 的稳定错误。
- 允许修改：账号创建输入、领域行为、错误、导出和对应单元测试。
- 明确不修改：持久化、Tauri、前端、编辑、删除和搜索。
- 实现步骤：账号名和密码按 trim 判空但保留原值；可选字段保留一致的空值语义；目标分类非空时必须存在；成功生成 UUID 并追加。
- 接口、数据与错误契约：稳定错误为账号名必填、密码必填、分类不存在；错误不回显字段值。
- 边界与异常：不校验地址或邮箱格式，不设置唯一约束。

- 预期结果：账号创建纯领域规则可独立验证。

## LPV-05-02 提交新增账号用例

- 状态：pending
- 支持的验收场景：创建成功持久化一次；失败保持旧列表；重开可读取。
- 唯一目标：`vault-app` 把一条账号创建作为一次串行确认提交。
- 当前行为与目标行为：应用层只提交分类；完成后可提交账号并返回安全快照。
- 前置条件与依赖：LPV-05-01。

- 实现步骤：锁定确认状态；克隆候选；创建账号；revision 加一；保存并重验；成功后替换状态并返回安全快照。
- 接口、数据与错误契约：快照账号摘要不含 password；领域和存储错误映射为稳定安全错误。
- 边界与异常：任何失败均不改变已确认文档和 revision。

- 预期结果：应用层账号写路径成立且失败可回退。
- 完成判定：测试证明确认后发布和失败不污染。
- 交付给下一原子的输出：Tauri 可调用的应用用例和安全摘要。
- 停止或重新规划条件：实现要求把未确认完整文档暴露给 command。
- 风险等级：L2
- DDD 门禁：直接测试足以证明失败不改变快照时不触发。
- 计划提交信息：`feat(app): [LPV-05-02] 提交新增账号用例`
