## 总体计划

- 产品结果：账号管理首页可查看近 7 天、近一个月、近半年和近一年的账号复制与密码复制次数，以紫红双折线展示，悬停可查看当日详情。
- 验收场景：没有记录时显示空状态；复制账号名只增加账号复制次数；复制密码只增加密码复制次数；切换四档时间后范围正确；X 轴不显示日期文字；靠近折线时显示日期及两项次数；重启后统计仍存在。
- 明确排除：显示密码计数、账号身份明细、任意日期范围、数据库、导出、复杂动画、整体界面调整和 Release 构建。
- 已确认架构：Windows 两个复制 command 在剪贴板成功后调用 `VaultApplication::record_account_used`；核心文档当前只有 `last_used_at`；`VaultSnapshot` 经 Tauri DTO 返回 Svelte；使用概览当前只是固定空占位。
- 数据不变量：事件只保存动作类型和 Unix 毫秒时间，不保存账号 ID、账号名、密码或其他账号字段；旧文档缺少事件字段时按空列表读取；记录失败不得替换已确认内存快照；事件集合保留 367 天有限滚动窗口，前端按本地自然日聚合且两类事件互不交叉计数。
- 执行模式：连续执行；每个原子独立验证、提交并同步 `origin/master`。
- 原子顺序：`LPV-14-01` → `LPV-14-02` → `LPV-14-03` → `LPV-14-04` → `LPV-14-05`。
- 整体回归：受影响 Crate 聚焦测试与 check、`npm run check`、`cargo test --workspace`、运行中的 Tauri Debug 增量编译与界面冒烟；不执行 Release。

## LPV-14-01 持久化成功的凭据复制事件

- 状态：done
- 支持的验收场景：账号名复制与密码复制产生可区分、可持久化的事件；旧密码库继续正常读取。
- 唯一目标：成功的凭据复制在现有最近使用保存中同步记录有限窗口的事件历史。
- 当前行为与目标行为：当前只覆盖账号的最后使用时间；完成后同一次候选保存还会追加动作类型和时间，并淘汰窗口外记录。
- 前置条件与依赖：LPV-11 已有剪贴板成功后保存路径和失败保持旧快照测试。
- 代码定位依据：`crates/vault-core/src/vault.rs` 的 `VaultDocument`、`record_account_used`；`crates/vault-app/src/lib.rs` 同名用例；`src-tauri/src/commands/vault.rs` 两个复制 command。
- 允许修改：核心使用事件模型与测试、应用层记录参数与测试、两个复制 command 的动作类型传递、计划状态。
- 明确不修改：前端响应结构、图表、显示密码行为、剪贴板清理、账号编辑和其他持久化流程。
- 实现步骤：在文档顶层增加带 `serde(default)` 的事件列表；事件只含类型和时间；记录时先确认账号存在，再更新 `last_used_at`、淘汰滚动窗口外记录并追加事件；账号名和密码复制分别传入对应类型。
- 接口、数据与错误契约：旧文档缺字段读取为空；系统时间为 0 的事件允许保存但不会进入近期图表；保存失败继续返回现有稳定错误并保留旧快照。
- 边界与异常：账号不存在时文档不变；不从旧 `last_used_at` 伪造历史；保留 8×24 小时以覆盖本地时区的最近 7 个自然日。
- 测试要求：旧文档兼容、两种事件区分、窗口淘汰、账号不存在不修改、应用保存成功及失败保持旧快照。
- 验证命令：`cargo test -p vault-core usage`；`cargo test -p vault-app credential_use`；受影响 Crate check；格式检查。
- 预期结果：后续快照可以读取真实事件历史，事件集合不会无限增长。
- 完成判定：聚焦测试通过，Workspace 保持可编译，旧文档兼容测试通过。
- 交付给下一原子的输出：当前确认文档中已有不含账号身份的使用事件。
- 停止或重新规划条件：新增默认字段导致现有文档无法读取，或事件必须包含账号身份才能满足图表。
- 风险等级：L3。
- DDD 门禁：实现前隔离审查“新增事件字段与有限窗口不会使现有密码库不可读或持续无界增长”。
- 计划提交信息：`feat(core): [LPV-14-01] 记录凭据复制事件`。

## LPV-14-02 暴露安全的使用事件摘要

- 状态：done
- 支持的验收场景：前端从每次真实密码库快照获得事件类型和时间，响应不包含账号身份或凭据。
- 唯一目标：沿现有 `VaultSnapshot → VaultStatusDto → VaultStatus` 暴露安全使用事件。
- 当前行为与目标行为：当前快照没有使用历史；完成后 Ready 快照和复制成功响应都携带同一事件摘要。
- 前置条件与依赖：LPV-14-01 已持久化使用事件。
- 代码定位依据：`crates/vault-app/src/lib.rs` 的 `VaultSnapshot`、`snapshot_from`；`src-tauri/src/commands/vault.rs` 的 `VaultStatusDto`；`frontend/src/lib/tauri/commands.ts` 的 `VaultStatus`。
- 允许修改：应用快照摘要、Tauri DTO 与转换测试、TypeScript 类型、计划状态。
- 明确不修改：新增 command、前端图表、事件写入规则、账号列表 DTO 和密码返回边界。
- 实现步骤：增加只含 `kind` 与 `occurredAt` 的摘要；从确认文档复制到快照；以 camelCase 判别值序列化；TypeScript 镜像该字段。
- 接口、数据与错误契约：响应不得含 accountId、username、password 或 notes；旧历史为空时返回空数组；现有字段保持不变。
- 边界与异常：非 Ready 启动状态仍不携带密码库摘要；搜索响应不重复携带事件。
- 测试要求：应用快照映射事件；Tauri DTO 序列化值正确且不含敏感字段；`svelte-check` 通过。
- 验证命令：相关 `vault-app` 与 Tauri DTO 测试；受影响 Crate check；`npm run check`；格式检查。
- 预期结果：Svelte 能从现有快照获得真实统计输入，无需新 command。
- 完成判定：协议测试和类型检查通过，Debug 增量编译成功。
- 交付给下一原子的输出：前端拥有可按本地日期聚合的事件数组。
- 停止或重新规划条件：DTO 必须暴露账号身份，或现有 Ready 联合无法承载新增安全字段。
- 风险等级：L2。
- DDD 门禁：直接序列化测试足以证明字段边界时不触发。
- 计划提交信息：`feat(app): [LPV-14-02] 暴露使用事件摘要`。

### 执行记录

- 实际验证：应用快照聚焦测试和 Tauri 安全 DTO 测试通过；`vault-app` 与 Tauri Crate check 通过；`svelte-check` 通过（0 error、0 warning）；Tauri Debug 增量编译并重新运行成功；格式和 diff 检查通过。
