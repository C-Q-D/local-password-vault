## 总体计划

- 产品结果：用户在账号编辑弹框中选择其他分类或“未分类”，与其他编辑字段一起保存后，账号列表和分类数量立即更新。
- 验收场景：账号可在两个用户分类之间移动，也可移至“未分类”；保存后原分类和目标分类数量同步变化；目标分类已不存在时拒绝整次编辑；保存失败时字段和分类均保持旧值。
- 明确排除：删除账号、搜索、复制或显示密码、批量移动、拖拽排序和整体视觉调整。
- 已确认架构：核心层提供独立的分类归属变更规则；应用层在同一候选文档中完成字段编辑和分类变更，并只持久化一次；Tauri command 扩展现有账号编辑请求；前端继续使用同一个保存按钮。
- 全局不变量：目标分类必须来自 Rust 当前确认快照；账号 ID 和其他账号不变；失败不发布候选状态；每次成功只增加一次 revision；列表 DTO 不增加密码字段。
- 执行模式：连续执行，三个原子分别验证、提交并同步。
- 整体回归：`cargo test --workspace`、`cargo check -p local-password-vault`、`npm run check`、Tauri Debug 冒烟；不执行 Release。

## LPV-08-01 更新账号分类归属候选

- 状态：in_progress
- 唯一目标：`vault-core` 支持按稳定 UUID 把账号移动到现有分类或“未分类”。
- 允许修改：核心领域行为、稳定错误和单元测试。
- 明确不修改：持久化、Tauri、前端和账号其他字段。
- 实现步骤：验证目标分类；定位账号；只替换 `category_id`；任一失败不修改候选文档。
- 错误契约：未知账号返回账号不存在；未知目标分类返回分类不存在；错误不携带输入内容。
- 测试要求：分类间移动、移至未分类、未知账号、未知分类、其他字段和其他账号保持不变。
- 验证命令：`cargo test -p vault-core move_account`；`cargo check -p vault-core`；格式和差异检查。
- 风险等级：L1。
- 计划提交信息：`feat(core): [LPV-08-01] 支持更新账号分类归属`

## LPV-08-02 原子保存账号字段和分类

- 状态：pending
- 唯一目标：应用层、Tauri 和 TypeScript 编辑契约接收分类 ID，并在一次候选保存中提交全部编辑。
- 允许修改：应用层编辑输入与编排、Tauri DTO、TypeScript 类型和相关测试。
- 明确不修改：Svelte 界面、列表明文边界和其他功能。
- 实现步骤：解析账号与分类 ID；锁定当前确认状态；在同一候选上更新字段和分类；revision 只加一；只在磁盘确认成功后发布。
- 错误契约：目标分类不存在使用 `CATEGORY_NOT_FOUND`；无效分类或持久化失败时字段编辑也不能生效。
- 测试要求：成功移动及计数更新；移动到未分类；目标分类不存在时零保存且状态不变；存储失败回滚全部编辑；Rust/TS DTO 一致。
- 验证命令：应用层和 Tauri 定向测试；`cargo check -p local-password-vault`；`npm run check`；格式和差异检查。
- 风险等级：L3。
- DDD 门禁：提交前隔离质疑“字段编辑和分类移动是否确实共享一个候选与一次保存，失败是否不发布”。
- 计划提交信息：`feat(app): [LPV-08-02] 原子保存账号分类变更`
