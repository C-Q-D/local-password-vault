# Local Password Vault 产品定义

## 背景与核心问题

用户需要在自己的 Windows 电脑上集中保存账号密码。现有明文文件缺少分类、搜索、密码隐藏和可靠编辑能力；完整商业密码管理器又包含大量当前不需要的联网、同步和扩展功能。

## 目标用户与使用情境

- 目标用户：项目所有者本人。
- 使用设备：用户自己的 Windows 电脑。
- 使用情境：记录和查找个人、工作、开发及其他网站账号；同一网站可能存在多个账号。
- 运行边界：只在本机使用，不依赖服务器、在线账户或外部 API。

## 项目目标与成功结果

提供一个启动后可直接使用的轻量桌面 App。用户能够自行组织分类，保存最少必要账号字段，快速搜索与复制账号，并在关闭、重启后继续读取正确数据。

成功结果必须可观察：

1. 用户可以创建分类并在分类中保存账号。
2. 同一网站的多个账号互不覆盖。
3. 必填与可选字段规则明确执行。
4. 非空分类不会被删除。
5. 搜索、编辑、复制和重新打开后的数据均正确。
6. 保存失败不会破坏上一次成功保存的数据。

## 第一版 MVP

- 启动后直接进入账号管理主界面。
- 用户自定义分类：创建、重命名、删除空分类。
- 系统视图：全部、未分类。
- 账号记录：账号名、密码、地址、邮箱、备注。
- 账号名和密码必填；地址、邮箱和备注可空。
- 同一网站可保存多个账号，不设置账号名或地址唯一限制。
- 账号新增、查看、编辑、删除和更换分类。
- 按账号名、地址、邮箱和备注搜索。
- 密码默认隐藏；支持临时显示、复制账号名和复制密码。
- 本地自动保存和重新打开后的持久化。

## 非目标

- 云同步、用户注册、服务器或多人共享。
- 浏览器插件、网页自动填充和手机端。
- 密码泄漏检测、强度报告和两步验证码生成。
- 标签、附件、自定义字段、回收站和独立设置页。
- 其他密码管理器格式的导入导出。

## 核心流程

1. 用户启动 App，直接看到账号管理主界面。
2. 用户选择现有分类、创建新分类或使用“未分类”。
3. 用户新增账号，填写必填字段并按需填写可选字段。
4. App 保存记录并在列表中展示；相同网站的其他记录保持独立。
5. 用户通过分类或搜索定位账号，然后查看、复制、编辑或删除。
6. 用户关闭并重新打开 App，继续访问上次成功保存的数据。

## 约束、风险与假设

- 数据包含现实账号密码，技术设计必须聚焦本地数据保护、原子保存、错误恢复和敏感信息不进入日志。
- 产品流程不增加服务器、同步、注册或多用户权限。
- 用户希望功能保持精简，未来功能只有在出现明确使用需求时才重新进入定义阶段。
- 本轮只确认产品功能，技术栈、存储格式与保护机制在技术设计阶段决定。
