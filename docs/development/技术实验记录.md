# Tauri 2 + Svelte 最小技术实验记录

## 1. 实验目的

本实验只回答三个问题：

1. Svelte 页面能否通过 Tauri 2 IPC 调用 Rust command 并拿到结构化结果；
2. 当前 Rust Workspace 与编译 profile 能否提供可接受的增量反馈；
3. 前端与 Rust 源码能否按明确模块边界组织，而不集中到单个目录或文件。

本实验不实现密码库业务、加密存储或平台能力。Release 构建与启动按照项目所有者要求推迟到全部功能完成后的发布候选阶段。

## 2. 固定环境与依赖

| 项目 | 实验版本 |
|---|---|
| Rust | 1.96.1，`rust-toolchain.toml` 固定 |
| Tauri Rust crate | 2.11.5 |
| Tauri CLI | 2.11.4 |
| Tauri JS API | 2.11.1 |
| Svelte | 5.57.0 |
| Vite | 8.2.2 |
| TypeScript | 6.0.3 |
| Node.js | 24.17.0 |

TypeScript 固定为 6.0.3，因为它已通过当前 `svelte-check` 版本的实际类型检查。依赖锁文件必须提交；日常开发不跟随最新大版本自动升级。

## 3. 最小调用链

```text
frontend/src/app/App.svelte
  -> frontend/src/lib/tauri/commands.ts
  -> invoke("check_stack")
  -> src-tauri/src/commands/experiment.rs
  -> StackCheckResult
  -> Svelte 页面展示返回消息和 Rust 版本约束
```

- 页面挂载后自动调用一次，也保留按钮供人工重复验证。
- Rust command 只返回非敏感实验信息，不访问密码库文件。
- `src-tauri/src/lib.rs` 只负责 Tauri 组装，`commands/` 按用途分文件。

## 4. 验证结果

| 验证 | 结果 |
|---|---|
| `npm run check` | 通过，0 错误、0 警告 |
| `npm run build` | 通过；JS 32.17 KiB，gzip 13.16 KiB |
| `cargo check -p local-password-vault` | 通过 |
| 实际修改 Rust 文件后的增量 `cargo check` | 0.53 秒 |
| `cargo test --workspace` | 通过，1 个实验 command 测试 |
| `npm run tauri -- dev` | Tauri 窗口成功启动；Vite 504 ms 就绪，Rust 增量启动构建 1.25 秒 |
| 真实 Svelte → Rust IPC | 通过；Rust 进程输出 `STACK_CHECK_COMMAND_INVOKED` |
| `cargo check -p vault-platform-windows` | 通过；`windows 0.62.2` 精确 feature 集可编译 |

首次 Rust 依赖冷编译明显慢于增量编译，符合预期。项目保留 `target`，不使用 `cargo clean` 作为日常操作。

## 5. 结论

- Tauri 2 + Svelte + TypeScript + Vite 能在当前 Windows 环境形成真实前后端闭环。
- Rust command、前端类型检查和 Debug 增量反馈满足进入开发规划的技术条件。
- Release 验证不是本实验的完成条件，后续只在功能全部完成、进入发布候选时执行。
